# Experiment 3 — synchronous ZeroMQ overhead

This is an external-computation systems experiment, **not an ML experiment**.
The statistical ZeroMQ backend evaluates the same deterministic egress budget as
the local PDES path. CODES remains authoritative for routing, max-min rates,
buffering, PAUSE, and event scheduling.

Scale matrix generated by `setup.sh`:

- 32 switches / 64 terminals: medium and high stress load
- 64 / 128: medium and high stress load
- 128 / 256: high stress load

The high point preserves the earlier stress workload (1000–4000 Gb generated
every four intervals); medium uses 300–600 Gb every four intervals. Every
PDES/statistical pair uses the same topology and RNG seed.

`run_all.sh` starts the ZeroMQ server, performs one unreported warm-up, runs five
measured repetitions by default, checks canonicalized committed CSV parity, and
optionally runs one debug diagnostic pass for per-request latency samples.

```bash
./experiment3/setup.sh
./experiment3/run_all.sh
```

Overrides: `REPEATS=3`, `RUN_DIAGNOSTICS=0`, `ZMQ_CLIENT_ENDPOINT=...`.
